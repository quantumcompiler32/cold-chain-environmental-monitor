Cold-chain event pipeline · Lesson 7

When the dashboard participates

Win for this lesson: you can identify exactly when the dashboard is involved and what each terminal proves.

When is the dashboard called?

The dashboard is not involved when the generator creates an event, when MQTT transports it, or while the subscriber validates and stores it. It participates after persistence:

event commits → adapter is notified → adapter reads event → browser receives data → dashboard renders

There are two ways this happens:

  • Page load or refresh: the browser gets HTML/CSS/JavaScript from port 8766, then JavaScript requests data from the adapter on port 8787.
  • Live update: the browser already has /api/live/stream open. A newly committed event wakes the adapter, which sends an SSE message, and the dashboard updates without a page refresh.

The dashboard is therefore a downstream consumer and presentation layer. It does not create, validate, or store the event.

What each terminal does

Terminal 1 · Subscriber

make start-listener LISTENER_OUTPUT_MODE=verbose

Runs backend.temperature_subscriber. It subscribes to MQTT, receives event JSON, validates it, derives operational state, writes both PostgreSQL projections, and reports accepted, duplicate, rejected, or database-error messages. This is the event writer.

Terminal 2 · Dashboard adapter

make start-dashboard

Runs backend.dashboard_bridge on port 8787. It serves API requests and the SSE stream, reads PostgreSQL in read-only transactions, and logs HTTP requests if logging is enabled. It does not write events. Its output may be quiet until a browser or curl calls it.

Terminal 3 · Static frontend server

python3 -m http.server 8766 --bind 127.0.0.1 --directory frontend

Serves files only: HTML, JavaScript, CSS, images, and other frontend assets. It does not query PostgreSQL and does not provide the event APIs. Its logs show requests such as GET /pages/domain-vaccine.html and GET /styles/shared.css.

Terminal 4 · Generator

make run-scenario SENSORS=Pod1 SCENARIO=mixed COUNT=5

Runs the simulator. It reads CSV guidance, creates event JSON, assigns IDs and timestamps, and publishes to MQTT. It does not display the dashboard. Its output shows generated/published events and scenario values.

How to watch the dashboard path

  1. Start Terminal 1, 2, and 3.
  2. Open http://127.0.0.1:8766/pages/domain-vaccine.html.
  3. Watch Terminal 3 for frontend file requests.
  4. Watch Terminal 2 for API/SSE requests.
  5. Start the generator in Terminal 4.
  6. Watch Terminal 1 for validation and persistence.
  7. Watch the browser update after the event commits.

To see the live stream directly, use a separate terminal:

curl -N http://127.0.0.1:8787/api/live/stream

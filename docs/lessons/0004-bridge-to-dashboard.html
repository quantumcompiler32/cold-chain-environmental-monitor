Cold-chain event pipeline · Lesson 4

From committed row to dashboard

Win for this lesson: you can explain why the bridge is read-only and how a notification becomes browser data.

PostgreSQL commit → NOTIFY → bridge wakes up → SELECT → HTTP/SSE response → browser

The bridge has two jobs

Query API: endpoints such as GET /api/events, /api/live, and /api/analytics query committed PostgreSQL data and serialize it as JSON.

Live stream: the bridge executes PostgreSQL LISTEN cold_chain_events. When a committed notification arrives, it uses the event ID to fetch the full row, then sends a Server-Sent Event (SSE) to connected browsers.

Why notify instead of sending all data?

The notification is a small wake-up signal. PostgreSQL remains the source of truth for the complete event. The bridge re-reads the committed row, which gives it the same consistent data as normal API requests and avoids putting a large payload in the notification.

Why read-only?

The bridge never starts the generator, listens to MQTT, inserts events, or changes disposition. It translates stored evidence into browser responses. This separation protects the event history: viewing the dashboard cannot mutate the data.

What is an API?

An API is a defined way for one program to request data from another. Here, the browser calls bridge URLs using HTTP. GET means “please read this”; the bridge responds with JSON.

What the endpoints mean

  • GET /api/events returns stored events in chronological order, with filters such as pod, vaccine, batch, scenario, severity, and time range.
  • GET /api/live returns a current live-monitoring snapshot. It is not the continuous connection.
  • GET /api/live/stream keeps an SSE connection open and sends newly committed events as they arrive.
  • GET /api/analytics reads events and computes counts for statuses, scenarios, phases, and severities.
  • GET /api/verification/latest-events returns a bounded newest-first view for verification.

In this repository, the bridge is the dashboard adapter: it adapts database-shaped data into a stable browser/API contract. The dashboard is the frontend pages and scripts that render that contract for a human. We’ll study that distinction in Lesson 5.
